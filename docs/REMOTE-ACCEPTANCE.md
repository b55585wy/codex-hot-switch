# 远程图文验收

人在外面时，可以在飞书的已绑定模块话题中要求 Codex 截图、说明结果，并等你给出下一步意见。

## 发起验收

直接在该模块话题发送普通消息：

> 请对本项目进行截图验收：打开当前页面，截取首页和关键交互流程，把真实截图直接发回本话题。每张图说明它验证了什么，并列出通过项、发现的问题和待我确认的事项。发完先等待我明确确认通过，再继续下一阶段；如果页面打不开或截图失败，说明具体原因。

有明确目标时，补充页面地址、登录状态、需要检查的操作和期望结果。例如：

> 验收当前项目首页和设置弹窗。分别截默认状态、打开弹窗、保存后的状态，说明按钮、排版和保存反馈是否符合要求。请把 PNG 保存到当前项目目录，再在最终回复中展示图片。

手机上收到图文后，可直接在同一话题回复：

- “通过，继续下一步。”
- “第二张图的按钮间距太小，改完重新截图。”
- “我发一张参考图，按图修改，再发对比截图。”

“等待我确认”是给当前会话的执行要求，不是平台级的强制审批锁；截图生成成功也不代表你已经验收通过。

## 让图片真正出现在回复里

Bridge 的飞书执行流会识别最终回答中的 Markdown 图片引用，并上传真实文件。应让会话先保存实际 PNG，再直接展示图片，而不是只回复磁盘路径。

示例格式为 `![验收截图](E:/demo/acceptance/home.png)`，路径应替换为实际存在的文件。最终回复中的图片引用放在普通 Markdown 内容中，不要放在代码块或内联代码里；上面的示例只是说明格式，不表示该文件已生成。

可以使用项目内相对路径、绝对本地路径或 HTTP(S) 图片。含空格的路径可放在尖括号内，例如 `![验收截图](<E:/demo/acceptance/home page.png>)`。

当前限制：单张图片不超过 10 MiB，一次最多处理 30 张；常用截图格式 PNG、JPG、WebP 均支持。非 full 模式应把图片保存在项目目录内，full 模式允许读取目录外图片。你发给机器人的截图会作为图片输入交给会话，一次最多九张。

## 两条通知路径的区别

| 场景 | 图片行为 |
| --- | --- |
| 在飞书已绑定话题发“截图验收”，由 Bridge 执行并回复 | 支持真实图片上传、卡片展示和图文反馈 |
| 原桌面会话独立运行，后台观察器推送完成摘要 | 当前仅转发文字摘要，不自动上传摘要里的图片 |

需要图片时，在已绑定话题明确发起截图要求。共享恢复会保留原会话的开发者指令，因此把截图保存位置、回传图片与等待确认的要求直接写在消息中更明确。

## 环境与验证状态

电脑需要保持开机，网络、Bridge 服务、目标页面和浏览器执行环境需要可用。截图执行能力取决于该会话实际可用的浏览器或截图工具；页面无法访问时应返回原因，而不是生成示意图冒充截图。

图片解析、真实文件读取和飞书上传路径已通过源码核对。本次整理仓库尚未完成从远程指令到实际截图回传的端到端实测，不能据此声称该验收流程已在当前机器完整验证。
