# 群会话控制（Group Controls）

群菜单与 `/controls` 是同一套**按用户、按会话**的服务端控制面。所有操作只作用于用户显式选中的**已有** Feishu 话题/会话；不会因为打开列表、查看帮助或分页而创建模型进程、会话或话题。

## 群菜单

Bridge 创建的群会安装三个原生群菜单（飞书一级菜单上限为三个），名称为中文：

| 菜单 | 链接 |
| --- | --- |
| 会话 | 本群常驻入口卡（稳定 message id） |
| 操作 | 同一个常驻入口卡 |
| 帮助 | 公共使用说明文档 `HELP_DOC_URL` |

原生群菜单只做链接跳转，不产生菜单事件。入口卡上的按钮才创建**每个用户独立**的一次性面板 token。用户选择确切会话后，才会看到继续、停止、目标等操作。

不能强制客户端自动展开群菜单；用户需要在输入框上方手动展开。

### 常驻入口卡的生命周期

- 入口卡是 **CardKit 实体**（card-by-reference），卡片 id 与承载消息 id 一起写入 `group-menus.json`；重启后按持久化的 card id 重新收养实体。
- 卡片更新的 `sequence` 必须是 `[1, 2147483647]` 内**严格递增**的 int32，服务端不会因为进程重启而接受回退值。每次更新（含重试）前都会在 `group-menus.json` 中**原子预留并持久化** `entrySequenceHighwater`；重启后从该值继续，绝不归零、不用时间戳、溢出时失败关闭。只有卡片实体 id 真正变化时才清零。
- node-sdk 的卡片回调去重会在 12 小时内按 `message + openId + 元素 + value` 判重，而常驻入口卡的按钮值本来不会变化。因此每次处理入口卡点击后，后端会**原地重渲染同一实体**，让按钮回调值轮换：下一次真实点击是新的 key（会触发），而同一点击的重投递仍是旧值（仍被幂等丢弃）。不关闭、也不绕过全局回调安全策略。
- 入口卡的 `message.create` 使用**发送前即持久化**的幂等 uuid；崩溃在“已发送、尚未记录 message id”之间时，重试用同一 uuid，平台返回原消息（而非再发一张常驻卡）。该 uuid 只作请求令牌，绝不当作 message id 使用；超出平台约 1 小时的幂等窗口后才会换新令牌。
- 若 CardKit 不可用而降级为普通 JSON 卡片：按钮回调仍可用，但只有第一次点击能被投递（无法原地轮换），此时请用 `/controls` 兜底。

### 安装与修复

- 新建群：`onboardGroup` 在确认群是刚创建的空群后安装入口卡与三个菜单。
- 老群：启动连接成功后，对 `origin=created` 的已有项目做一次**有界、串行、非致命**的回填；不会重发欢迎卡或 Pin。
- `origin=joined` 的群自动跳过；管理员可在群内执行 `/controls setup` 显式修复/回填。
- 安装元数据写入当前 bot 目录下的 `group-menus.json`（版本化、原子替换）：常驻入口 message id / card id、菜单 id、状态与诊断信息。
- 重复启动不会重复创建入口卡或菜单；入口消息被删除时只重建本 Bridge 拥有的入口卡与菜单。
- **读失败不写**：菜单树读取失败时无法得知现状，默认**不做任何写入**（不盲建旧版帮助菜单、不落状态），只报告 `menu-tree-unavailable`。旧版单菜单兜底仅在调用方**明确知道群是空的**（新建群 onboarding）时通过 `fallbackLegacyMenu: true` 启用；老群/回填/管理员修复一律关闭。
- **归属以签名证明，不以 id 为准**：删除自有菜单前必须同时匹配精确的 `name + link` 签名（含历史入口链接与旧版 `🤖 <后端名>` 签名）。若某个已存 id 对应的菜单被用户改名/替换，签名不再匹配 → 视为他人菜单，不删除。
- 更新自有菜单采用“先删自有项、再创建”的方式（飞书没有 menu_tree update API）。若一级菜单槽位不足或存在任何非本 Bridge 菜单，保留全部现状并报告 conflict：**没有强制覆盖开关**，需要用户自行清理后再执行 `/controls setup`。
- 拿不到入口消息的 `message_app_link` / `message_position` 时不生成死链；保留 `/controls` 兜底并报告未完整安装。

## `/controls`

- `/controls`：打开新的按用户选择器。
  - `project.kind === 'single'`：该群只有一个隐式会话，直接打开它的面板。
  - 其它（多话题群）：**即使只有一个会话也必须显式选择**，绝不自动选最近会话；没有会话时显示明确空状态。
- `/controls setup`：仅 bot 管理员可用，对本群执行显式修复/回填（允许 joined 群）。
- `/controls` 属于明确命令，遵循原有 mention 策略。

## 面板与授权

- 面板 token 绑定：群 chat、操作者 open id、选中的原始 session key、原始 session id/backend/cwd、项目权限签名。
- TTL 约 15 分钟；pending map 有界（64）。token 一次性，在第一次 await 前同步消费；重复/重放回调只会得到安全的过期结果。
- 每次操作都会重新读取服务端状态：群/用户白名单、项目权限签名、持久化会话映射、当前 active 运行状态、账号切换状态。
- 其他用户、其他群、过期、重放、会话被删除/改绑、权限或配置变化、账号切换、排队/运行中任务均 fail closed。

### 权限层级（tier）归属

- 当项目配置了独立的 guest 沙箱，会话 key 会带 `#admin` / `#guest` 后缀；无后缀的是历史共享会话。
- `#admin` 会话**仅限管理员**：非管理员在列表里看不到它，也不能用伪造/残留的 `select` 回调进入面板；继续、停止、启动目标、结束目标在**最终落库前**都会按“当前是否管理员”重新校验——管理员被降权后，旧面板 token 也会被拒绝。
- 目标 key 只能**降低**、不能**提升**调用者的权限：管理员操作 `#guest` 会话仍以 guest 沙箱运行（保持目标范围），guest 操作 `#admin` 会话直接拒绝，绝不会“静默改绑”或以 guest 模式跑管理员会话。
- 无后缀的历史会话保持原有一次路由语义：按调用者当前角色选沙箱，不因控制面而改变。
- 停止/结束目标沿用现有 `runOwnerOrAdmin` 语义：仅该轮发起人或管理员可操作。

## 操作语义

- **继续**：仅空闲的已有会话。通过原始话题的既有 run 路径派发一条明确的 `继续`，使用新的合成入站 id（不与来源卡 id 去重），sender 为实际操作者，会话/话题保持原样；不新建隐藏话题或映射。
- **停止当前轮次**：仅普通运行；调用选中 `ActiveState.interrupt`，不影响其他运行。目标运行中不显示此操作。
- **启动自主目标**：仅支持目标且空闲的会话。目标内容非空、最长 1000 字；确认后走既有 goal run 路径，锚定原始会话/话题。后端不支持时服务端拒绝。
- **结束目标并停止**：仅当前目标运行，发起人或管理员可用；调用既有 goal `interrupt` 路径（清除目标并停止当前轮次），**不使用** `endGoal`（后者会允许进行中的轮次跑完）。回执只表示“已请求”，不声称目标已清除。

卡片输入框中的内容永远作为目标文本直接提交，不会被解析为任意斜杠命令。

## 回退

菜单不可用、scope 缺失、安装冲突或客户端未展开菜单时，在群内使用 `/controls` 即可；能力与菜单入口完全一致。
