# 私有版实现与运行边界

本版把一个原 Codex session 视为可以长期负责某个模块的工作上下文。飞书话题保存与原 session 的关联，`/module` 保存独立的模块名，最近任务与原生会话标题不相互覆盖。

## 构建结构

`src/` 保留上游 TypeScript 实现；`extensions/` 保存共享会话接入、模块列表、完成追踪、精确恢复入口、话题通知与超时去重扩展。构建流程先执行上游构建，再应用扩展，得到 `dist/`。

这是一套明确针对上游 `v0.6.14` 的构建后扩展，并非已将全部改动移植进上游 TypeScript 模块。安装器会检查版本和预期代码布局，布局变化时停止应用。后续维护需要同时评估上游源码和扩展锚点。

```powershell
npm ci --ignore-scripts
npm run build
npm run test:extensions
npm test
```

构建、测试结果以实际命令输出为准。测试覆盖原 ID 保留、权限和目录边界、重复话题、通知去重、错误恢复、重启、goal 状态与超时后的完成推送。

## 原会话与共享后台

恢复已有会话遇到 `already has an active writer` 或 `thread-store conflict` 时，Bridge 通过本机 `codex app-server proxy` 连接共享后台，并加入原 session。

共享接入保留原 session ID、模型配置、权限、开发者指令和 goal。共享后台连接失败或返回错误会话时，保留飞书绑定并报错。关闭 Bridge 的共享连接只关闭它自己的代理连接。

共享后台的审批可能仍需原客户端处理；本版没有承诺在飞书中接管所有原生审批。截图验收属于对会话下达的工作要求，见 [远程图文验收](REMOTE-ACCEPTANCE.md)。

## 恢复与模块命名

私聊和项目群中的 `/resume <完整 ID>` 会独立查询本机原生会话元数据。按 Windows 路径规范化、大小写和真实目录边界匹配项目，优先选择最具体的父目录。它不会仅根据最近会话选择列表判断 ID 是否存在。

管理员检查在查询和绑定前执行，目标群也检查访问权限。相同群、相同后端和相同原 session ID 会复用已有话题。首次关联使用目标群内的消息作为话题锚点。

`/module 前端界面` 应在负责该模块的话题中发送。它设置 Bridge 显示名，保留原生会话标识与上下文。

## 完成提醒与重试

已绑定会话优先在所属模块话题发送完成结果并 @ owner；未绑定会话发 owner 私聊。普通交互式咖啡完成卡仍走原来的私聊处理。读取绑定或投递已有话题发生错误时，不会把一次未送达的群消息记成已成功私聊。

后台观察器只读本机原生会话元数据、goal 状态和 JSONL 记录，每五秒检查新事件。首次启动从已有记录末尾开始，避免把历史任务全量补发。中间输出、子代理和用户中断保持安静；goal 为 active 时不发单轮完成提醒。

受阻通知由明确终态触发：`task_complete.error` 或带当前轮次的最终错误。流重试事件保持安静，不因错误文本包含“capacity”就判断任务已停止。飞书管理的执行流同时检查 `turn/completed` 的 `failed` 状态，错误详情缺失时也不会把失败显示为成功。最终失败即使 goal 仍为 active 也会通知；goal active 只阻止普通单轮完成提醒。

容量不足、额度或认证等错误作为原因显示在原模块话题，未绑定时发 owner 私聊。原 session 保留，用户可稍后在原话题发送“继续”，或更换可用模型后继续。本版不自动替换模型、不发送无限重试的新任务；服务端仍在重试时不额外推送。失败和成功分别去重，失败提醒不会屏蔽后续真实成功。

本机 Codex 0.165 的失败记录包含 `turn_id`、`error.message` 和 `error.codex_error_info`；模型容量不足对应 `server_overloaded`。如果某个客户端只显示错误弹窗、没有写入可关联当前轮次的终态记录，后台观察器不能保证捕获。首次启动仍不补发旧记录。

通知以原 session、轮次和目标位置生成稳定请求 UUID。第一次失败后进行一次短间隔重试；继续失败则保留持久队列，按 60、120、240、300 秒退避，最长五分钟。重启后恢复待发送状态。新一轮任务、中断或关闭通知时，会取消过时的待发送提醒。

本地去重记录与飞书发送分属两个系统，不能把它视为跨进程崩溃和网络边界的严格恰好一次事务。

## 超时的含义

默认 watchdog 是连续 120 秒没有收到匹配当前会话及轮次的进展事件，随后结束本轮卡片跟踪。界面的总耗时不是该阈值，话题绑定也不随它失效。

共享 daemon 中，断开 Bridge 的跟踪连接不能证明原任务已经停止；独立 app-server 关闭可能终止其任务。因此卡片只说明本轮跟踪超时，并提示查看原会话状态。

超时、错误、中断和取消提醒不会写入“最终完成已通知”记录，后续真实完成事件仍可推送。在原话题发送下一步指令时，Bridge 根据保存的原 ID 自动重连，通常无需再次手工 `/resume`。

咖啡模式默认 600 秒的完成卡回复窗口与 watchdog 分开设置。该窗口结束不等于话题解绑。

## 部署和数据

运行需要 Node.js 24、可访问的飞书网络与本机 Codex。使用 `CODEX_HOME` 时，原生会话读取跟随该目录。

配置、凭据和会话数据保留在本机运行目录。源码仓库不需要真实机器人账号、项目注册表或聊天记录才能构建和运行隔离测试。

替换现有安装前先验证构建与测试，再选择部署时机。直接升级上游 npm 包可能覆盖扩展；版本变化后应重新验证布局、协议和数据格式。
