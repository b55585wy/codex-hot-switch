# Codex 飞书 Bridge · 私有定制版

本仓库新增 **多终端 Codex 账号热切换与飞书原生菜单**。安装、启动和验收说明见 [HOT-SWITCH.md](HOT-SWITCH.md)；飞书私聊可用 `/runtime` 查询账号、`/runtime usage` 查询额度、`/runtime switch <账号>` 切号。

Bridge 自建项目群现在自动安装 **会话 / 操作 / 帮助** 菜单，已有自建群在启动后补装。控制卡按用户选择原会话，提供继续、停止当前轮次、设置目标及结束目标并停止；多话题群先选会话，外部群结构不会自动修改。使用与权限边界见 [群会话控制说明](docs/GROUP-CONTROLS.md)，命令入口为 `/controls`，管理员修复入口为 `/controls setup`。

在飞书里管理长期负责某个模块的 Codex 会话：运行中保持安静，完成后把结果发回对应话题；你也可以发截图验收要求，再回复修改意见或确认通过。

本项目基于 [modelzen/feishu-codex-bridge](https://github.com/modelzen/feishu-codex-bridge) `v0.6.14`，保留完整上游源码，并在构建后应用本仓库的扩展。来源和许可证见 [UPSTREAM.md](UPSTREAM.md)。

## 多台电脑怎么区分

当前可直接使用的方式是 **每台电脑使用独立的飞书机器人（不同 App ID）**，再把项目群命名为 `MacBook｜哈尼网站`、`Windows｜论文实验`。群名方便人辨认；程序根据群的 `chatId` 查找本机项目目录，改群名不会把任务转到另一台电脑。

不要在多台电脑上同时启动同一个 App ID 的 Bridge：飞书长连接会把事件随机交给其中一个客户端，不会按群名选择电脑。当前没有跨电脑设备路由；同一个机器人控制多台电脑需要新增统一中转服务和设备端连接。安装步骤、命令作用范围和待实现的中转设计见 [多电脑部署说明](docs/MULTI-COMPUTER.md)。

## 在飞书里使用

额度耗尽时，可私聊管理员原生命令 `/account` 查看 CC Switch 已存账号，`/account status` 查询共享后台登录。此入口不调用模型；实际切号需要本仓库提供的 CC Switch 适配版。完整命令、构建步骤和恢复边界见 [原生账号入口](docs/ACCOUNT-CONTROL.md)。

1. 在机器人管理台关联项目目录和项目群。
2. 在机器人私聊或项目群发送 `/resume <完整会话 ID>`，关联原 Codex 会话。
3. 在生成的模块话题内发送 `/module 前端界面`，设置长期保留的模块名。
4. 后续任务和反馈都发在该话题；模块名与最近任务分开显示。

已有绑定会优先复用。私聊的精确 ID 命令按会话真实目录选择项目群，不受“最近会话列表”数量限制；目录存在多个同样具体的项目群时，在目标群发送同一命令即可确定目标。

例如，在同一个模块话题发送：

> 请完成当前页面，然后打开页面进行截图验收。截取首页和关键交互流程，直接把真实截图发回本话题，附上通过项、发现的问题和待我确认的事项。发完先等待我明确确认通过，再继续下一阶段。

收到图文后，可以回复“通过，继续下一步”，或“按第二张图修改按钮间距，改完重新截图”。完整说明见 [远程图文验收](docs/REMOTE-ACCEPTANCE.md)。

## 这个版本增加了什么

| 功能 | 行为 |
| --- | --- |
| 原会话接入 | 遇到共享后台写入锁时，重新加入原 daemon 会话，保留原 session ID 和 goal；连接失败保留原绑定 |
| 模块列表 | 长期模块名、最近任务、最近活动分开显示；同一原会话的重复话题合并展示 |
| 精确恢复入口 | 私聊和项目群都支持 `/resume <ID>`；在已绑定话题发后续指令时自动重连 |
| 完成提醒 | 已绑定会话优先回复模块话题并 @ owner；未绑定会话发机器人私聊 |
| 安静运行 | 不转发中间执行过程；goal 仍为 active 时不把单轮结束当作整个目标完成 |
| 失败恢复 | 通知保留在持久队列，退避重试；稳定消息 UUID 减少重试重复投递 |
| 超时去重 | 超时提醒不再被记作最终完成通知，避免屏蔽稍后真正的结果 |
| 受阻提醒 | 最终失败（包括模型容量不足）推送错误原因和原会话入口；Codex 内部仍在重试时保持安静 |
| 图文回传 | 飞书发起的执行流可上传真实图片并在回复中展示，支持你继续发图提出修改意见 |

共享 daemon 的审批仍可能需要原客户端处理。普通咖啡模式的交互卡继续使用原来的私聊路径。独立桌面会话的后台完成观察器目前只转发文字摘要，不会自动把摘要中的图片引用上传成图片。

“Selected model is at capacity” 导致本轮最终失败时，通知显示“任务受阻”，不会显示为成功。原 session 和话题绑定保留；可在原话题稍后回复“继续”，或更换可用模型后继续。通知不能消除服务端容量限制，本版不会自动换模型或无限重发任务。

## 本地构建

使用 Node.js 24 或更新版本。共享会话扩展最初基于 Codex `0.165`；原生账号入口已按本机 `0.166.0` 验证。其他版本应重新验证协议和本地数据格式。

```powershell
npm ci --ignore-scripts
npm run build
npm run test:extensions
node bin/feishu-codex-bridge.mjs --help
```

`npm run build` 先构建上游 TypeScript，再按顺序应用 `extensions/` 中的扩展。`npm test` 运行上游测试；`npm run test:extensions` 运行私有扩展的需求与回归测试。

首次配置和机器人权限参考 [上游 README](docs/UPSTREAM-README.md)，安装和更新使用本仓库的构建产物。已有运行中的机器人时，先构建验证，再计划替换安装；同一个机器人无需同时启动两个 Bridge 后台。

首次创建机器人配置后，启用本版完成监听和话题优先通知：

```powershell
npm run setup:private -- --bot YOUR_APP_ID
npm run setup:private -- --bot YOUR_APP_ID --apply
node bin/feishu-codex-bridge.mjs start
```

第一条仅预览，不输出凭据；第二条备份并更新已有配置，不重新创建机器人。已有后台需先停止，再应用配置并用 `start` 恢复后台和登录自启。配置与凭据保留在本机，不提交到仓库。

## 时间与通知

- 本轮卡片总用时不是会话有效期，话题绑定不会在十分钟后过期。
- 默认 watchdog 为连续 **120 秒没有收到当前会话进展事件**后结束本轮跟踪。共享会话断开 Bridge 连接不等于原任务已停止。
- 咖啡模式默认 **600 秒回复窗口**是另一项设置。
- 后台完成观察器独立保留；任务实际完成后仍可通知。若任务已停止，在原话题发“继续”即可让 Bridge 自动重连原 session。

完整行为、边界和扩展结构见 [私有版说明](docs/PRIVATE-EDITION.md)。电脑、网络和 Bridge 服务需要保持可用；页面验收还需要项目页面或浏览器环境可访问。

## 代码与本机数据

仓库保存上游源码、扩展、测试和文档。机器人凭据、令牌、会话记录、真实项目注册表、通知队列与本机日志保留在本机运行目录，不纳入仓库。

本版扩展使用构建产物的明确布局校验，并锁定上游 `0.6.14`。升级或重新安装上游 npm 包可能覆盖定制功能，应在新版本上重新验证扩展后再部署。
